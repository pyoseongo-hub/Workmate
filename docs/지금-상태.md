> "처음부터 하나하나 집어 가며 다시할거야"
> "지금주는 자료는 참고하고 **반영은 나에게 필요한부분 설명후 해**"
> "나는 **초보자**라 자세하고 간단한 설명이 필요해"

- **한국어로, 쉽게.** 전문용어를 쓰면 그 자리에서 풀어 준다

- **틀린 것을 짚어 주면 변명하지 않고 고친다.** 이 사람은 판단이 빠르고 정확하다

## ⌨️ 시작 명령어

```bash
cd /home/user/workmate
pnpm install
```

### 실제로 돌려 볼 때 (이걸 쓴다)

```bash
pnpm build                       # 화면 + 서버를 한꺼번에
PORT=3000 node dist/server.js    # http://localhost:3000
```

DATABASE_URL 이 없으면 **메모리에만** 담는다(서버 끄면 사라짐). 검사용으로는 충분하다.

### 그 밖에

```bash
pnpm check                       # 타입 검사 — 커밋 전에 반드시
node scripts/make-preview.mjs    # 미리보기 HTML 한 장으로 묶기
pnpm test                        # vitest (옛 뼈대 것이라 지금 화면과 무관)
```

### ⚠️ `pnpm dev` 는 반쪽이다

`pnpm dev` 는 `server/_core/index.ts` 를 띄운다. **매장 API(`/api/stores`)가 없다.**
화면은 뜨지만 자료가 서버로 안 가고 브라우저 안에만 남는다(공유가 안 됨).
`pnpm dev:server` 는 정적 파일 경로가 어긋나서 404 가 난다.

**화면 모양만 만질 때가 아니면 `pnpm build` + `node dist/server.js` 를 쓸 것.**

### 브라우저로 손으로 눌러 보는 검사

Playwright 가 깔려 있다. 크로뮴 경로를 반드시 지정한다:

```js
chromium.launch({ executablePath: "/opt/pw-browsers/chromium-1194/chrome-linux/chrome" })
```

서버를 배경으로 띄울 때는 `setsid` 를 쓴다. 안 그러면 명령이 끝날 때 같이 죽는다:

```bash
setsid nohup env PORT=3000 node dist/server.js > /tmp/srv.log 2>&1 < /dev/null & disown
```

## 🚫 되돌리지 말 것 (사장님이 정한 방침)

1. **급여·휴게시간·수당을 셈하지 않는다.**
   `Shift` 에 `breakMinutes` 칸을 **일부러 안 만들었다.** 넣지 말 것.
   화면에서도 "안 하는 일"을 **말하지 않는다.**

2. **만든 것만 말한다.** 홍보 문구에 "○○는 안 합니다" 를 넣지 않는다.

3. **브라우저 `confirm()` / `alert()` 을 쓰지 않는다.** `useConfirm` 을 쓴다.
   (이유는 아래 사고 기록)

4. **목록을 고칠 때는 반드시 함수 꼴로.**
   `setShifts((prev) => ...)` ○ / `setShifts([...shifts, 새것])` ✗

## 🩹 겪은 사고와 교훈

### ① 삭제가 안 됐다 — `confirm()` 이 조용히 거짓말한다

앱을 안전 상자(iframe sandbox) 안에서 열면 브라우저가 `confirm()` 창을 **안 띄운다.**
그런데 오류를 내지 않고 **조용히 `false`(취소)를 돌려준다.**
→ 앱은 "사용자가 취소했구나" 하고 넘어간다. 화면엔 아무 일도 안 일어나고 오류도 없다.
근무·교대·근무일지·직원 **네 곳이 전부** 이래서 먹통이었다.
→ `useConfirm` 으로 앱이 직접 창을 그린다.

### ② 동시에 고치면 한 명 것이 사라졌다

목록을 통째로 덮어쓰는 구조라, 사장님과 알바생이 **8초 안에** 각자 근무를 넣으면
나중 사람이 앞사람 것을 지웠다. **오류도 안 떴다.** 사람 수와 무관한 버그였다.
→ 판 번호(version). 맞을 때만 저장하고, 어긋나면 서버가 최신 목록을 돌려준다.
   앱이 거기에 자기 것을 **다시 얹어서** 보낸다(최대 4번).

### ③ 켜 두기만 해도 서버를 1분에 43번 불렀다

자료 종류마다 각자 8초 시계를 갖고 있었고, 부를 때마다 매장 자료를 **통째로** 내려받았다.
1년 쓴 매장은 한 번에 471KB. 바뀐 게 없어도, 화면을 안 보고 있어도 그랬다.

| | 전 | 후 |
|---|---|---|
| 1분당 호출 | 43회 | **8회** |
| 8초마다 내려오는 양 | 471 KB | **68 B** |
| 하루 8시간 | 9.3 GB | **0.7 MB** |
| Render 무료로 버틸 사람 | 0명 | **6,713명** |

→ ⓐ시계 하나로 합침 ⓑ판 번호만 묻고 바뀐 것만 받음 ⓒ화면 안 보면 멈춤

### ④ 고치다가 깨뜨린 것 — 검사가 잡아 줬다

②③ 을 고친 뒤 **알림을 읽어도 종 배지가 안 사라졌다.**
종과 알림 목록이 같은 자료를 각자 보는데, "판 번호가 그대로면 안 받아 온다"로
바꾸는 바람에 서로를 모르게 됐다.
→ 저장한 쪽이 같은 자료를 보는 화면들에 직접 알린다(`notifyListeners`).

**교훈: 성능을 고치면 "저절로 맞춰지던 것"이 같이 끊긴다. 검사를 꼭 다시 돌린다.**

### ⑤ 그 밖에 걸렸던 것

- `Card` 에 이미 `py-6` 이 있다. `p-5` 를 더하면 여백이 두 배 → **`py-0` 을 붙인다**
- 달력 `min-w-[680px]` 이 폰에서 수·목·금·토를 잘랐다 → `min-w-full sm:min-w-[680px]`
- 사람 색은 **목록 순서가 아니라 `member.id`** 로 고른다. 앞사람을 지우면 색이 우르르 바뀐다
- 첫 화면이 12.7초 걸렸다 → 개발용 스크립트 358KB 를 뺐더니 **0.2초**
